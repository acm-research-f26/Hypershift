# Study FB scientific audit (FBA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Audit HyperShift Study FB and the wider programme independently: recompute the headline statistics, run cheap diagnostics, verify the literature, and ship one report covering the seven requested deliverables.

**Architecture:**
- New package `src/hypershift/fbaudit/` holds the statistics and diagnostics. It imports FB code read-only and never edits any freeze-hashed file.
- Scripts in `scripts/fbaudit_*.py` write their tables to `docs/audit_20261022/`. Refit outputs go to `results/FBAUDIT_20261022/`.
- Zero-refit diagnostics run first, then at most ~40 local LightGBM refits plus Ridge fits. Literature claims are verified by web search before being cited.

**Tech Stack:** numpy, scipy, sklearn, lightgbm 4.7 (`.venv`), yfinance (unadjusted Close + Dividends fetch only).

**Spec:** the user's pasted prompt "HyperShift — Deep Scientific Review, Methodological Audit, and High-Value Research Roadmap", Parts 1–13 and Deliverables 1–7. A copy is saved as `docs/audit_20261022/REQUEST.md` in Task 1.

## Global Constraints

- **Freeze-hashed files are read-only.** These files must not change:
  - `src/hypershift/featbench/{data,models,prospective}.py`
  - `scripts/featbench_prospective.py`
  - `src/hypershift/screening/{data,metrics}.py`

  The test `test_freeze_hashes_unchanged` re-hashes them (CRLF→LF, sha256) against `FREEZE_MANIFEST.json` and runs last.
- **FB artifacts stay as they are.** Never write into `results/FEATBENCH_SP500_20261022/` or rewrite any file in `docs/featbench_20261022/`. The only permitted change there is one appended pointer line in `FB_REPORT.md`.
- **No new market data beyond what FB already touched.** Shifted labels drop any signal whose label needs a price index greater than `max(evaluate) + 5` in that fold. The yfinance fetch covers 2014-06-01..2024-01-12 only.
- **Everything is exploratory.** All of 2015–2023 has been inspected before, and no audit number is confirmatory.
- **Verdict words** keep the FB definitions: SUPPORTED / NO EVIDENCE. The audit adds the categories Established / Suggestive / Unsupported / Untested / Compromised for findings.
- **Commits** go to `tom-shlom` locally. Never push. `docs/HANDOFF.md` stays uncommitted.
- **Refit budget:** about 40 early-stopped or 300-round LightGBM fits, plus 50-round and Ridge fits, all on local CPU with `CUDA_VISIBLE_DEVICES=-1`.

### Predeclared thresholds (fixed before any audit number is computed)

- **T1. Non-superiority margin δ = 0.010** neutral RankIC. That is about the pooled level of the best simple signals (reversal16 +0.007, l1 +0.011), so an improvement of δ would roughly double them.
  - "Can rule out an improvement ≥ δ" requires the one-sided 95% upper bound (the 90% two-sided stationary-bootstrap CI) to be below δ.
  - Equivalence (TOST) requires both 90% bounds inside ±δ.
- **T2. Post-hoc neutralisation.** Let G = (residual-target) − (raw-target) at seed 7, and G_n = (raw-target predictions neutralised ex ante on the residual exposures) − (raw-target).
  - **"Mostly tilt removal"** if G_n ≥ 0.5·G and residual − neutralised-raw has a 95% CI that includes 0.
  - **"Learning gain"** if residual − neutralised-raw ≥ 0.5·G with CI lower bound > 0.
  - Otherwise **"mixed"**.
- **T3. Execution lag**, judged on the next-close label (close t+1 → close t+1+h) against the same-close label:
  - **"robust"**: retains ≥ 50% of the pooled same-close neutral RankIC and the CI lower bound is > 0;
  - **"bounce-dominated"**: retains < 25%;
  - otherwise **"partial"**.
- **T4. Matched fixed-round target test.** "Target effect robust to rounds" requires residual − raw ≥ +0.007 with ≥ 4/5 folds positive at both 50 and 300 rounds.
- **T5. Dividend leak** is **material** if any one of these holds:
  1. the median per-date Spearman correlation between adjusted and corrected `log_dvol_20` is below 0.95;
  2. the leak term used as a scorer has a pooled neutral RankIC whose 95% CI excludes 0;
  3. any corrected-refit contrast (residual − raw, rich − price) moves by more than 0.005 from the original.
- **T6. Power.** MDE = 2.8 × SE (80% power, two-sided α = .05). Days needed scale as SE²·days.

## Review Focus

1. **Shifted-label index overflow at the 2023 fold end.** Signals whose label needs data past FB's touched range must be dropped, not wrapped or zero-filled (`test_shifted_labels_drop_tail`).
2. **Neutralising predictions on dates with fewer stocks than regressors.** Return the input unchanged and never NaN (`test_neutralise_pred_thin_date`).
3. **Recompute disagreeing with the saved daily series.** It must be reported, not hidden: assert `max|diff| < 1e-6` and print the result (`test_recompute_matches_saved`, data-marked).
4. **Bootstrap with block length ≥ n.** It must not crash (`test_bootstraps_long_block`).
5. **Corrected-dividend features misaligned by ticker or date.** Assert ticker identity, and assert that adjusted-close ratios between the fetch and the stored OHLCV are constant per stock to within 1e-3 over shared dates (`fbaudit_dividends.py` alignment check).

**Interfaces (Produces):**
- `stats.spearman_daily(pred[S,N], y[S,N], mask[S,N], minimum=20) -> [S]`. This is fresh code: rank via `scipy.stats.rankdata`, then Pearson on the ranks.
- `stats.stationary_means(x, block, B, seed) -> [B]`

- `stats.nw_se(x, lags) -> float` (Bartlett kernel)
- `stats.pooled(series_by_fold: dict, method, block, B=5000, seed=0) -> dict(pooled, se, ci95, ci90, p, per_fold)`, with pooled = mean of fold means and the bootstrap averaged per fold as in FB.
- `stats.nonoverlap(x, h) -> list of h subsample means`
- `stats.load_daily(root, year, arm, seed=7, key='neutral_RankIC') -> (values, dates)`

- `diag.exposures(fb, signals, kind) -> [S,N,K]`:

  - `kind='full'` gives sector dummies + z(beta, log_dvol_20, ret_60, vol_60) over eligible stocks.
- `diag.neutralise_pred(pred, expo, mask) -> pred residuals`: per-date OLS. Dates with mask.sum() ≤ K + 1 are returned unchanged.

### Task 3: Selection bias and portfolio diagnostics (zero refits)

**Files:** create `scripts/fbaudit_selection.py`, which writes `docs/audit_20261022/A3_SELECTION_PORTFOLIO.md`.

**Pool:** the 17 h = 5 Ridge/LightGBM arms:

- `{ridge,lgbm}:rich:{sector,residual}`;
- `{ridge,lgbm}:rich:raw:5:{raw,cs_rank,sector_z,volscaled_z}`.

The script asserts the pool has 17 arms.

- [ ] **Step 1: Selection-bias analyses.**
  - **(a) Leave-one-fold-out:** select on the other 4 folds and score the held-out fold. Report the mean held-out value and how often the full-sample winner is chosen.
  - **(b) Winner stability:** stationary bootstrap (block 10, B 2000) resampling the joint daily matrix within folds; P(argmax = each arm).
  - **(c) Hansen SPA/White RC p-values:** best arm vs 0 and best arm vs rev16, recentred, B 2000.
  - **(d) CSCV PBO** (Bailey et al.): 10 chronological blocks, all C(10,5) splits; PBO plus the median out-of-sample rank of the in-sample best.
  - **(e) Shrinkage:** empirical-Bayes James–Stein shrinkage of the 17 pooled means toward their grand mean using the bootstrap SEs; report the shrunk value of the winner.
  - **(f) Sign probability:** P(5/5 folds positive) under the null of independent symmetric folds is 1/32, against the count of pool arms with 5/5 positive.
- [ ] **Step 2: Portfolio diagnostics**, using `portfolio.weights_rule` and `simulate` (read-only imports) for rev16, lgbm:rich and lgbm:rich:residual × rules B and D:
  - gross vs net Sharpe, and gross ann. return vs cost drag = 252 × 0.001 × turnover;
  - break-even one-way cost;
  - ex-post daily beta and the per-date style exposure (`full`) of the net book;
  - a "pure-alpha book": daily P&L = Σ w·(1-day neutral return).
  - The long-only rule A gets an HAC (NW lags 5) regression of net returns on the EW market: alpha (ann.), t, beta.
- [ ] **Step 3: Data checks.**
